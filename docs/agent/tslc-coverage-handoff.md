## New mechanisms (vocabulary added by the final four — reuse these)

Each was added per the charter ("a new type/keyword earns its place only when it lets
a primitive compile that couldn't before"):

- **Non-vector free functions** (`allocate` family). `SignatureShape.is_free_function`
  (`catalog/signatures.py`): true when result + all params ∈ `{ptr, usize, void}` (no
  vector-projected kind; `s` is excluded so `memory_cp` stays per-type). The selector
  emits ONE ISA-independent slot (iterating the impl's own type-group member, e.g.
  `ptr`); `cpp.py`/`rust.py` emit a plain `tsl::name(...)` free function (prototype in
  declarations, body in definitions) instead of a `simd<>` template. `_cpp_smoke`
  address-takes `&tsl::name` (no template args).
- **`mem` keyword** (`region_handlers/memory.py`): `mem<copy|set|alloc|alloc_aligned|
  free>(...)` → `mem_*` translate templates. Rust runtime helpers in `tsl_core.rs` use
  the **C allocator via `extern "C"`** (malloc/aligned_alloc/free) so `free(ptr)` needs
  no `Layout`; mirrors C++ `std::*`. `void` pointer casts map to `u8`/`c_void` in Rust.
- **Variadic `s...` kind + `pack` keyword** (`set`). The arity = lane count, computed
  per spec (`LoweredSpecialization.variadic_lanes` / `LoweringEnv.variadic_lanes`).
  C++ renders a variadic template (`Args... args` → `_mm_set_epiN(args...)`); Rust
  reuses the `s[]` array param (`Self::Array`). `pack<expand>(args)` → C++ `args...` /
  Rust `args[0..N-1]` (cast to signed-of-base for the int set intrinsics; floats pass
  through); `pack<first>(args)` → C++ `tsl::pack_first(args...)` / Rust `args[0]`.
  Variadic primitives **skip the generic `<LANES>` vector** in selection (a C++ pack
  can't be runtime-indexed) — preserving parity.
- **`o` kind + `io` keyword** (`to_ostream`). `o` (a text buffer) → C++ `std::string&` /
  Rust `&mut String` (the return lifetime elides — `out` is the only ref param).
  `io<format>(buffer, array, modifier)` → an `ostream_write(out, arr, modifier)` runtime
  helper that owns the per-lane base formatting (so the body is just `to_array` →
  `io<format>` → `emit_return(out)`). Rust gets a `TslBits` (`as_u64`) trait, exactly
  the `TslByteCount` pattern from the `mem` work.

## The core working loop (how coverage gets made)

This is the repeatable method — still the right loop for the remaining *quality* work
(reducing skip counts, fixing a body, adding a primitive to a fresh corpus).

1. **Pick a primitive (or family)** from the inventory's skip column (the
   "dominant gap" tells you why slots skip), or any newly-authored primitive.
2. **Probe lowering first (fast, no compile).** Use **`generation_mode="strict"`** to
   turn coverage-gap (`info`) skips into surfaced errors — this is how you see *why* a
   slot doesn't generate:
   ```python
   PYTHONPATH=tslc/src python -c "
   from pathlib import Path; from tslc.api import generate_project
   r=generate_project([Path('tsldata')],
     machine_profiles_path=Path('supplementary/buildsystem/machine_profiles.json'),
     primitives=['NAME'], profiles=['scalar','sse2','avx2','skylake','icelake-rockerlake'],
     generation_mode='strict')
   from collections import Counter
   print('errors', Counter((d.code, d.message[:55]) for d in r.diagnostics if d.severity=='error'))
   print('emitted', Counter((e.primitive,e.backend,e.extension) for e in r.coverage))
   print('skips', Counter(s.reason[:60] for s in r.skipped))"
   ```
   Pick profiles where the primitive actually emits a non-empty set. (Drop
   `generation_mode` for the normal lenient view.)
3. **Add a build test** in `tslc/tests/test_build_verify.py` (copy the boilerplate;
   group by family so the call-graph closes — the pipeline pulls callees via
   dependency closure automatically). Comment what builds and what skips cleanly.
4. **Run it** (see "Running tests" — serial, single session!). The build either
   passes (promote to verified) or surfaces a **real codegen bug**.
5. **Fix the bug**, re-run, repeat. Then run the regression set (any verified test
   touching files you changed), regenerate the inventory, run the non-build suite.

### Where bugs live, by symptom (from experience)

- **`details::FOO` undefined (C++) / `details::FOO` is invalid (Rust)** → a
  scalar-core helper isn't ported. Add it to BOTH `tslc/src/tslc/backend/assets/
  tsl_core.hpp` (template fn) and `tsl_core.rs` (trait + `details::` fn). Port
  semantics from `frozen/supplementary/cpp/runtime_support.hpp`. Helpers added so
  far: `arith_add/mul/rem`, `popcount`, `ctz`, `clz`, `mask_test`, `mem_copy`/
  `mem_alloc`/`mem_free`, `pack_first`, `ostream_write`, and the `TslByteCount`/
  `TslBits` traits (Rust). Charter rule: only add a helper when a primitive needs it.
- **Rust emits C++ syntax** (e.g. `i8 result = (0 as i8);`, `mem<copy>(...)`,
  `name<Vec>(...)`) → the `.tsl` body used a **raw C++ construct** instead of a
  backend-neutral TSIL region. Fix the *source*: `type<gen>(T) x = v;` →
  `var<typed>(type<gen>(T), x, v)`; `details::mask_test<Vec>(m,i)` → `mask<test>(m,i)`.
  Raw text passes through verbatim (per charter), so C++-only spellings break Rust.
- **Rust "comparison operators cannot be chained" on `foo<bar>`** → a keyword that
  isn't scanned leaks as raw text (`<` parsed as less-than). Either it should be a
  region or (if a Rust identifier) needs escaping.
- **Rust type mismatch returning a count** (e.g. `details::ctz(...)` returned where
  `BaseType` expected) → C++ converts implicitly, Rust doesn't. Wrap the body in
  `cast<static>(type<generation>(base::in), ...)`.
- **`<primitive>` is a Rust keyword** (e.g. `mod`) → handled centrally now by
  `rust_raw_identifier` in `tslc/src/tslc/backend/rust_translation.py` (emits
  `r#mod`), applied at the wrapper name and `render_call`.
- **Body wrongly selected on a profile lacking a feature** → a `requires` /
  type-group grouping bug in the `.tsl` (see the `compress` VBMI2 case below).

## Reference: the mask model (needed for any masked/bit primitive)

Masks have two *physical* representations that the `lane_bitmask` repr_kind
conflated:
- **integer bitset** — generic vector (`u64`), avx512 (`__mmaskN`/`uN`), scalar
  (`bool`). Test lane i with `(mask >> i) & 1`.
- **register lane-mask** — sse/avx2: the mask IS a data register
  (`__m128i`/`__m256i`), each lane all-ones/all-zeros. Test lane i by extracting
  its base-sized chunk and checking nonzero.

`mask<test>(m, i)` lowers per repr (`tslc/src/tslc/lower/region_handlers/masks.py`):
the lowerer remaps `lane_bitmask` + `vector_bits > 0` → a `lane_register` key.
- bitset → inline template `mask_test_lane_bitmask` (`(m>>i)&1`) in
  `tsldata/detail/lang/translate_{cpp,rust}.tsl`.
- register → `mask_test_lane_register` template → the universal helper
  `tsl::details::mask_test<Vec>` (C++ `if constexpr is_integral`) /
  `Self::mask_lane_test` (Rust default method on `SimdVector`, byte-chunk).

Per-extension facts: `scalar` bool/vb0, `generic` lane_bitmask/vb0, `sse`/`avx2`
lane_bitmask/vb128-256 (→register), `sse_vl`/`avx2_vl`/`avx512`
native_predicate_by_lanes (→`__mmaskN` integer). Check with a tiny script over
`catalog.extensions[name].mask_policy.kind` / `.vector_bits`.

## What remains (the campaign is done; this is quality work)

All 89 primitives build-verify. There is **no remaining build-coverage work**. In
rough value order:

1. **Behavioral verification (the big gap).** The build only *compiles* the generated
   code (the C++ smoke address-takes every wrapper; Rust `cargo test` compiles the
   crate). **Nothing runs a primitive against expected outputs.** The `.tsl` files carry
   rich `tests:` blocks (inputs/expected per type) — wiring those into a generated test
   harness that actually executes and checks results is the natural next campaign. Note
   the build-verify *shims* that compile but are not behaviorally complete: Rust
   `mem_free` (now real, libc), and the `set`/`to_ostream` formatting are plausible but
   unverified against the `tests:` expectations.

2. **Generic (`<LANES>`) coverage — 83/89; the last 6 are blocked by stable Rust, not
   effort.** Raised 64→83 via: `type::size_bytes` query, `vector::imask` resolving to the
   concrete `ui64` on scalar/generic, lifting the stale masked-on-generic selector guard,
   and generic representation-change *target* vectors (`_resolve_target_vector` builds
   `simd<ToBase, generic<LANES>>` for the BASE dim — this is why `reinterpret`/`cast` work:
   they preserve the lane count). The remaining 6 are a **hard ceiling**, verified — do not
   re-attempt without one of the escapes below:
   - `convert_up`/`convert_down`/`load_convert_up` (width-changing) and `extract`/`insert`
     (sub-register) need an **output lane count derived from `LANES`** (e.g. `LANES/4` for
     i8→i32, same byte width). Stable Rust **forbids** a const-generic expression as a type
     argument (`Generic<{LANES/4}>` / a register `[T; LANES/4]` → *"generic parameters may
     not be used in const operations"*, the nightly-only `generic_const_exprs`). C++ can
     express it; tslc requires both backends to compile, so it's blocked. Re-parameterizing
     the tag by bits/bytes does NOT help — a *derived* array length (`[T; BITS/32]`) is
     rejected the same way; only a *standalone*-sized buffer (`[u8; BYTES]`) compiles.
   - `set` — variadic; its C++ form is a parameter pack, which can't be runtime-indexed for
     a generic loop.
   - Escapes (all rejected as disproportionate for ~5 SIMD-reshape primitives): nightly
     `generic_const_exprs`; a byte-buffer generic substrate (`Generic<BYTES>` + `[u8; BYTES]`
     register + reinterpret access — rewrites all 83 working generic bodies); or threading a
     separate non-derived output-lane const generic per repr-change (render plumbing + the
     output lane count leaks into the API).
   When you DO add a generic body (for a same-lane-count op), expect the same latent
   raw-decl/type bugs (`T x = …;` → `var<…>`; `!= 0` on floats → `!= cast<static>(base::in,
   0)`); mirror a sibling that compiles (e.g. `hand` for `hor`).

3. **Reduce other in-primitive skip counts** (deferred slots — skips, not failures).
   Check the inventory's "skipped slots" / "dominant gap" columns. Known:
   - unresolved `type<generation>`/`value<generation>` queries — the `select(...)` query
     (gates `hand`/`hor` float generic), `vector::mask_underlying_t` (store_mask_repr unpacked),
     etc. Add `QueryFunction` classes in `tslc/src/tslc/lower/queries.py` (one class + one
     registry entry each; `type::size_bytes`/`SizeBytesQuery` is the worked example).
   - dependency-closure pruning (e.g. `to_ostream` shows "pruned (closure)" slots): a
     body's callee isn't generated for that profile, so the slot is dropped. Usually
     benign; investigate with `strict` mode if a slot you expect is missing.

4. **Corpus/cleanup carryovers.** The original `to_ostream` design's staged multi-op
   `io_*` templates (C++ `ostream <<`; Rust `crate::tsl` io macros) are now **unused** —
   `to_ostream` uses the single `io_format` helper instead. Likewise the `mem_set`
   translate templates and `memset` path are staged but unexercised (no primitive uses
   `mem<set>` yet). Safe to leave; remove in a cleanup pass if desired.

## Critical environment gotchas (WILL bite you)

- **Never write under `/tmp`.** WSL: `/tmp` is the container overlay (VHDX only
  grows). All scratch/output goes under **`./tslctmp`** (workspace 9p mount). The
  harness scratchpad path is under `/tmp` — do NOT use it; use `./tslctmp`.
- **Run pytest serially — one session at a time.** Both `pytest.ini` and
  `tslc/pyproject.toml` fix `--basetemp` under `tslctmp/`. Two concurrent pytest
  sessions (or an `rm -rf tslctmp/...` during a run) **wipe each other's basetemp
  mid-run** → spurious `FileNotFoundError`/`Directory not empty`/"nothing
  verified". **This is exactly the `verify.sh` `FileNotFoundError: ...
  tslctmp/pytest_build_verify` symptom** — the basetemp vanished mid-run. Mitigate:
  `rm -rf tslctmp/pytest*` only when nothing is running; don't run `verify.sh`
  alongside another pytest; `mkdir -p tslctmp` defensively.
- **Toolchain**: build verification needs `cmake` (C++) and `cargo` (Rust); the C++
  compiler is `CXX` (or `--cpp-compiler`, default `c++`), the Rust one `RUSTC` (or
  `--rust-compiler`). Since `8b634a8` the verifier runs a **compiler preflight**: an
  unusable/missing toolchain → the backend is *skipped* (recorded in `report.skipped`),
  NOT failed — so a green build test with `report.commands` empty means it never
  compiled. The build tests assert `report.commands` is non-empty to guard against
  that; if confirming a real compile, check `report.skipped == []` too.
- **`PYTHONPATH`**: `tslc` tests resolve via their own conftest, but running tslc
  modules/scripts directly needs `PYTHONPATH=tslc/src` (the root `pytest.ini` now
  points at `tslc/src`; a bare `pytest` at the repo root runs the tslc suite).
- Build tests are slow (~30–60s each; the full file is many minutes). Run targeted
  subsets in the background and poll.

## Worked example: the `compress` VBMI2 bug (selector/requires gotcha)

`compress`'s `[sse, sse_vl]` block grouped `[?i16, ?i32, ?i64]` under one
`requires [avx512f, avx512vl, sse, sse2]`, but `_mm_maskz_compress_epi16` needs
**AVX512_VBMI2** (only epi32/epi64 are F+VL). On Skylake-X (has avx512vl, lacks
vbmi2) the i16 body was wrongly selected → compile error. Fix: split `?i16` (with
`avx512_vbmi2`) from `[?i32, ?i64]`, mirroring the already-correct `[avx2,
avx2_vl]` block. Lesson: when one type in a grouped selector needs extra features,
split it out; check intrinsic feature requirements per type.

## Charter reminders (don't regress on these)

- Behavior-preserving refactors only unless adding real capability.
- No helper/type without a primitive that needs it (e.g. don't add a
  `vector::offset_base` query — it was vestigial; we dropped the dummy arg instead).
- `.tsl` expresses backend-neutral intent; raw C++/Rust spellings in bodies are
  bugs (they only work for one backend).
- Keep C++/Rust at parity (every primitive emits the same extension set for both;
  the inventory verifies this).
