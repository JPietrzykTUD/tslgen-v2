## Goal

Make `tsldata/extensions/extension.tsl` a typed ground-truth source for
extension metadata that later selection, type lowering, backend type spelling,
and primitive-call selector matching can consume without hardwired extension
tables.

The accepted extension facts include:

- extension identity and existing metadata such as `vendor`, `extension_name`,
  `inherits`, `family`, `intrinsic_style`, `vector_bits`,
  `native_sort_order`, `autodetect`, `lscpu_flags`, `mask_repr`,
  `mask_width`, `mask_vector_loadable`, `runtime_lanes`,
  `default_test_target`, `test_sizes_bits`, backend support blocks, signature
  support, and test filters;
- vector register type facts for native fixed-width extensions;
- a compile-time lane-count fixed-array policy for `generic`, not a
  runtime-growing Rust vector;
- scalar register policy where the vector register type is the base type;
- separate `mask_type_policy` and `integral_mask_type_policy` facts.

clearer `.tsl` encoding. If a spelling changes, update the docs in this

For scalar:

```tsl

  ...
  vector_register_type_policy:
    kind "base_type"
```

For generic, model the reusable library type as lane-count-parametric fixed
arrays. The generator may use `test_sizes_bits` for concrete generated tests,
but the library type must not require generation-time knowledge of the user's
chosen vector size.

```tsl
extension generic:
  ...
  vector_bits "sized"
  size_parameter:
    kind "lanes"
    name "LANES"
  vector_register_type_policy:
    kind "fixed_array"
    element "base_type"
    length "LANES"
  mask_type_policy:
    kind "lane_bitmask"
    width "lanes"
  integral_mask_type_policy:
    kind "lane_bitmask"
    width "lanes"
```

The Rust consequence is a compile-time fixed array shape such as
`[T; LANES]`, not `alloc::vec::Vec<T>`. Avoid generic const expressions like
`[T; BITS / size_of::<T>()]` in stable Rust-facing design.

Mask policies:

```tsl
extension sse:
  ...
  mask_type_policy:
    kind "lane_bitmask"
    width "lanes"
  integral_mask_type_policy:
    kind "lane_bitmask"
    width "lanes"

extension avx2:
  ...
  mask_type_policy:
    kind "lane_bitmask"
    width "lanes"
  integral_mask_type_policy:
    kind "lane_bitmask"
    width "lanes"

extension neon:
  ...
  mask_type_policy:
    kind "lane_bitmask"
    width "lanes"
  integral_mask_type_policy:
    kind "lane_bitmask"
    width "lanes"
```

For `lane_bitmask`, the semantic valid bit count is exactly the lane count.
Backends may choose the smallest unsigned storage type that can hold that many
bits, for example 4 valid bits stored in `u8` / `std::uint8_t`.
