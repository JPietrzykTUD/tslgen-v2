## Accepted State

Accepted through:

```text
Milestone 254.1: Fragment-First Implementation Body Ownership
```

M254.1 split the pure recursive source-body fragment model into
`tslgen.syntax.source_body_fragments`, attached optional
`source_body_fragments` to domain `Implementation`, promoted full `tsil`
bodies into fragment sequences during catalog building, and migrated backend
type-query discovery to prefer fragments when present. `ImplementationBody`
remains explicit removal debt.

## Goal

Continue the M254.x removal series by migrating the remaining raw source-island
discovery family from `ImplementationBody.tokens` scans to fragment-derived
facts when `Implementation.source_body_fragments` is present.

## Scope

Implement the smallest coherent family slice:

- Add fragment-first discovery entry points for raw-island families that
  currently scan raw token runs:
  - backend value queries;
  - backend intrinsic requests;
  - source operations;
  - backend output source islands;
  - mask keyword requests;
  - mask lane constant requests.
- Update family-level production functions or `Lowerer` wrappers so
  `implementation.source_body_fragments` is preferred whenever present.
- Keep old `ImplementationBody.tokens` scanners only as compatibility fallback
  for tests and not-yet-migrated callers.
- Preserve accepted text helpers and typed semantic lowering results. Raw
  fragments may delegate to existing `*_in_text` helpers; recognized keyword
  fragments may become typed request facts directly only when the source-body
  scanner already owns that keyword family.
- Add focused tests using selected implementations with real or synthetic
  fragment sequences and empty compatibility tokens to prove migrated families
  do not depend on `ImplementationBody.tokens` when fragments are available.
- Preserve deterministic diagnostics for malformed raw-island forms.
- Record the remaining `ImplementationBody` accounting and create M254.3 unless
  production/test references have disappeared.

## Non-Negotiable Guardrails

- No new TSIL keyword semantics.
- No broadening of accepted source forms beyond already documented keyword
  families.
- No new parser.
- No pairwise handlers such as `emit_return + intrin_compose`, `call +
  value`, `loop + mask`, or deeper ancestor-specific combinations.
- No backend rendering, build verification, dependency closure, semantic
  `@self` resolution, generic loop code generation, assignment/index expression
  parsing, source repair, target-language operator parsing, or template-side
  semantic decisions.
- Do not make `ImplementationBody` more central. Any remaining token path must
  be compatibility fallback and named or documented as such.
- Do not introduce runtime dependencies on `frozen` or `tslgenold`.
