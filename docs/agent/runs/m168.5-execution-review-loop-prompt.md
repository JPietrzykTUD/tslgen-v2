## Goal

Add a typed primitive-local declaration for optional `return_type` bindings:

```text
return_type:
  base: UserChosenIdentifier
```

or:

```text
return_type:
  extension: UserChosenIdentifier
```

The identifier name is arbitrary source data. `ToBase`, `ToExtension`, and
similar names are examples from the corpus, not generator keywords.

The intended domain shape is a small typed declaration on `Primitive`, for
example:

```text
Primitive.return_type_binding: ReturnTypeBindingDeclaration | None

ReturnTypeBindingDeclaration:
  kind: base | extension
  name: Identifier
  source: SourceLocation
```

If `return_type` is absent, the primitive has no return-type binding. Do not
model this as an unconstrained semantic dictionary and do not add concrete
selected values in this milestone.

## Design Guardrails

- The `.tsl` primitive declaration is the source of truth for the binding
  name.
- `return_type` may be absent. That is a normal case, not a diagnostic.
- A declared name is primitive-local. It is not a global generator keyword.
- This milestone stores declarations only. M169 will bind concrete selected
  values and teach lowering to resolve identifiers from selected context.
- Do not add selected specialization bindings, type-symbol lowering, selector
  tree parsing, wildcard expansion, dependency closure, expression parsing, or
  renderer behavior in M168.5.
- Do not implement a general YAML-like parser for real `tsldata` primitives.
  The real corpus inventory is evidence; the clean restart parser should accept
  only the selected exact fixture form needed for this boundary.
- Do not add broad registries, dispatchers, worklists, callback maps, hidden
  backfeeds, or fixpoint machinery.
