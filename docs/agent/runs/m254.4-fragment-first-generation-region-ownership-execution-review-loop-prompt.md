## Goal

Continue the M254.x `ImplementationBody` removal series by migrating
generation-region ownership toward the canonical recursive source-body
fragment boundary.

## Scope

Implement the smallest coherent generation-region slice:

- Add fragment-first entry points for accepted generation-control and
  generation-loop region consumers that currently parse `ImplementationBody.tokens`.
- Prefer `implementation.source_body_fragments` whenever present and retain
  old token paths only as compatibility fallback for token-only tests/callers.
- Reuse the existing accepted semantics for:
  - `if<generation>(Condition) { ... }`
  - `else<generation> { ... }`
  - `else if<generation>(Condition) { ... }` where the current token path
    already accepts it;
  - `loop<unroll>(...)`;
  - `loop<range>(Index, Start, End, Step) { ... }`.
- Preserve accepted condition/value lowering, malformed-region diagnostics,
  unsupported-selector diagnostics, and deterministic selected-branch or
  loop-body facts.
- If preserving existing result models requires converting a fragment body
  slice into compatibility tokens, quarantine that conversion behind one
  narrow helper or adapter and document it as removal debt. Do not spread new
  `ImplementationBody` construction through production code.
- Add fragment-backed selected-implementation tests with empty compatibility
  tokens, plus token-only fallback tests where existing tests do not already
  prove fallback.
- Record exact remaining `ImplementationBody` references and use that
  accounting to select the next M254.x prompt.

## Non-Negotiable Guardrails

- No new TSIL keyword semantics or keyword spellings.
- No broadening beyond already accepted generation-control/loop forms.
- No pairwise surrounding-keyword handlers.
- No new parser.
- No backend rendering, build verification, dependency closure, primitive-call
  selector specialization, semantic `@self` resolution, generic loop code
  generation beyond existing accepted loop-region facts, assignment/index
  expression parsing, source repair, target-language operator parsing,
  template rendering, CLI work, or template-side semantic decisions.
- Do not make `ImplementationBody` more central. Any remaining token path must
  be compatibility fallback or quarantined removal debt.
- Do not introduce runtime dependencies on `frozen` or `tslgenold`.
- Do not reactivate M255 while production body lowering still depends on
  `ImplementationBody`.
