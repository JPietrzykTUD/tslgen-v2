## Accepted State

Accepted through:

```text
Milestone 254: Real Generic Unmasked Binary Arithmetic Body Lowering
```

M254 proved that the shared recursive source-body fragment boundary can see
the real generic unmasked `add`/`sub` body shape, including
`var<init_register>`, `loop<unroll>`, `loop<range>`, nested
`value<generation>`, nested `call<primitive=...>`, nested `type<backend>`,
and `emit_return` regions.

Post-M254 architecture correction:

```text
ADR-073: Source Body Fragments Supersede ImplementationBody Token Scanning
```

M254 exposed a high-risk split: the recursive fragment tree owns the new body
structure, while older semantic discovery paths still scan
`ImplementationBody.tokens`. M255 is deferred until the M254.x series starts
removing that split.

## Goal

Start the M254.x removal series:

- make recursive source-body fragments the production implementation-body
  discovery boundary;
- turn `ImplementationBody` into explicit removal debt;
- remove or quarantine direct `ImplementationBody.tokens` source scanners;
- preserve accepted typed semantic behavior by feeding it from fragments, not
  by creating another source parser or pairwise keyword path.

This milestone is successful when the production path has one obvious
source-body owner and the next M254.x removal step is concrete.

## Scope

Implement the smallest coherent consolidation slice that materially reduces
`ImplementationBody` dependence:

- Inventory every production `ImplementationBody` reference under
  `tslgen/src/tslgen` and classify each as source discovery, semantic
  evaluation, compatibility plumbing, rendering/pipeline consumer, or model
  definition.
- If the current recursive fragment classes cannot be consumed outside
  lowering without improper imports, split or move the pure source-body
  fragment model so catalog/domain code can use it without importing semantic
  adapters.
- Ensure full `tsil` implementation bodies enter production lowering as
  recursive `SourceBodyFragmentSequence` values or a pure equivalent, not only
  as rescanned `emit_return(...)` payloads.
- Replace at least one production category of direct `ImplementationBody.tokens`
  source scanning with fragment-derived typed facts.
- Quarantine any remaining `ImplementationBody` compatibility path behind one
  clearly named temporary adapter that is fed from the fragment tree.
- Add tests that prove the real M254 generic body still exposes the same nested
  regions and that the migrated category no longer performs independent raw
  token scanning.
- Add guardrail tests or static checks that reject new pairwise surrounding
  keyword handlers, fixture-shaped body pipelines, and new production scanners
  over `ImplementationBody.tokens`.

## Non-Negotiable Guardrails

- Do not add new TSIL keyword semantics as part of the cleanup.
- Do not add a new parser.
- Do not add pairwise handlers such as `loop + call`, `emit_return + call`, or
  deeper ancestor-specific combinations.
- Do not add backend rendering, build verification, dependency closure,
  semantic `@self` resolution, generic loop code generation, assignment/index
  expression parsing, source repair, target-language operator parsing, or
  template-side semantic decisions.
- Do not make `ImplementationBody` more central. Any new reference must be
  temporary compatibility code that reduces the remaining dependency.
- Do not introduce runtime dependencies on `frozen` or `tslgenold`.
