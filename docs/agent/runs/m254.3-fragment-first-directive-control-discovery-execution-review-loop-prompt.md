## Goal

Continue the M254.x `ImplementationBody` removal series by migrating the next
structural directive/control discovery families to fragment-first ownership.

## Scope

Implement the smallest coherent structural slice:

- Add fragment-first discovery entry points for already accepted directive or
  control families that currently consume `ImplementationBody.tokens`, with
  priority on:
  - generation variable declarations (`var<...>(...)`);
  - backend control directives (`if<compile>`, `else<compile>`,
    `switch<compile>`) where the existing accepted request model applies.
- Prefer `implementation.source_body_fragments` whenever present and retain
  old token paths only as compatibility fallback for token-only tests/callers.
- Convert already-scanned keyword fragments into the existing typed request
  facts only for accepted selectors and accepted source forms.
- Preserve the existing diagnostics for malformed selectors, payload arity, and
  unsupported selectors.
- Add fragment-backed tests with empty compatibility tokens, plus token-only
  fallback tests where existing coverage does not already prove fallback.
- Record exact remaining `ImplementationBody` references and use that
  accounting to select M254.4.

## Non-Negotiable Guardrails

- No new TSIL keyword semantics or keyword spellings.
- No broadening beyond already accepted directive/control forms.
- No pairwise surrounding-keyword handlers.
- No new parser.
- No backend rendering, build verification, dependency closure, semantic
  `@self` resolution, generic loop code generation, assignment/index
  expression parsing, source repair, target-language operator parsing, or
  template-side semantic decisions.
- Do not make `ImplementationBody` more central. Any remaining token path must
  be compatibility fallback and named or documented as such.
- Do not introduce runtime dependencies on `frozen` or `tslgenold`.

## Required Review/Audit Subagents

After implementation and validation, run read-only subagents:

1. Architecture/boundary reviewer: fragment-first ownership; no new parser,
   pairwise keyword paths, backend rendering, source repair, or increased
   `ImplementationBody` centrality.
2. Evidence reviewer: migrated families match already accepted TSIL/source
   forms; remaining `ImplementationBody` references are accurately classified.
3. Test reviewer: fragment-backed empty-token coverage, token fallback,
   diagnostics, and guardrails.
4. Documentation reviewer: roadmap/state/spec consistency and next M254.x
   prompt accuracy.
5. Validation auditor: exact validation results, `rg` accounting output, and
   workspace hygiene.

If any reviewer returns `Needs Revision`, make only focused fixes for the
blocking issues and rerun the relevant focused review. If any returns
`Return To Planner` or `Reject`, stop implementation and create the appropriate
next prompt.
