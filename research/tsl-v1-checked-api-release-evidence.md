# TSL v1 checked-API release evidence

Date: 2026-09-06
Reviewed implementation: Slice 8 completion `cb32a29e`
Pre-refactor source: `08954770`

This report records the documentation, typed-contract compatibility, package,
and mechanism measurement results produced by Slice 8. The later
post-implementation review supersedes it as a release-readiness decision:
transitive-precondition accounting and exact backend declaration compatibility
remain open. It is also not a claim that one workstation microbenchmark
predicts application performance.

## Public contract and inventory

The generated C++ and Rust overviews now state the same two-path contract:

- an unsuffixed operation performs the requested work without hidden input
  sanitization;
- Rust marks that operation `unsafe` when violating its caller contract can
  cause undefined behavior;
- a `_checked` twin exists only when the compiler can validate the complete
  catastrophic runtime precondition before invoking the ordinary operation;
- C++ value operations return the ordinary value and write a final
  `precondition_error&`; callers must inspect it before using the candidate;
- Rust uses `Result<T, PreconditionError>`; and
- valid C++ spans, Rust references/slices, object lifetime, provenance, and
  concurrency remain language-level caller obligations rather than facts that
  TSL pretends to validate.

The typed v1 public baseline contains 181 primitive callable families,
44 C++ algorithm families, 35 C++ checked-algorithm families, 174 Rust
algorithm callable names, nine C++ core identities, and eight Rust root
identities. It now records complete source signature semantics, checked
condition descriptors, error spellings, and algorithm contracts. Focused tests
cover representative rendered declarations, but no exact backend declaration
manifest exists yet.

The checked census contains 33 exact public callable identities with at least
one caller-unsafe implementation. Twenty-two have source contracts from which
complete twins can be projected; eleven are explicit omissions. Those omissions
are the mask-representation load/store variants, pointer-indexed narrow gather,
deallocation provenance, and raw byte copy. They require a typed layout,
ownership, or byte-range contract before an honest checked signature exists.
The exact identities and omission reasons remain in
[`tsl-v1-checked-api-census.md`](tsl-v1-checked-api-census.md).

## Documentation gates

The focused scalar C++/Rust project for `extract_value_at` and `allocate`
generated 2,842 specializations across 54 artifacts. The following gates passed:

- strict Doxygen identity validation over the primitive facade, core types,
  data-parallel policies, and ordinary/checked algorithm headers;
- `RUSTDOCFLAGS='-D warnings -D missing_docs' cargo doc --no-deps
  --no-default-features`;
- 207 Rust doctests discovered, with the two overview checked/unchecked examples
  executed and 205 comprehensive generated snippets intentionally ignored;
- the checked C++ overview example compiled under GCC and Clang with
  `-Wall -Wextra -Werror`; and
- the Sphinx site linked the shared contract, C++ Doxygen output, Rustdoc, and
  specialization explorer.

Every value-returning checked C++ example branches on `precondition_error`
before moving the candidate into caller-visible output. The Rust example
pattern-matches `IndexOutOfBounds`.

## Mechanism showcase

The maintained consumers are
[`checked_api_showcase.cpp`](../supplementary/benchmarks/checked_api_showcase.cpp)
and
[`checked_api_showcase.rs`](../supplementary/benchmarks/checked_api_showcase.rs).
They benchmark runtime lane extraction, signed `i32` division, and aligned
contiguous load. Each runs a handwritten/raw path, the unsuffixed TSL path, a
checked valid path, and a checked failure path. Inputs pass through a compiler
barrier, every result contributes to a checksum, and every checked candidate is
consumed only after its error was inspected. The harness rejects an unexpected
error kind: failure runs matched the operation-specific error exactly
5,000,000 times, and zero valid-path runs reported an error.

Host: Intel Xeon w5-3425, Linux x86-64, process pinned to logical CPU 6. The TSC
is invariant, but frequency, thermal state, and system-wide contention were not
controlled. Values are one pinned five-million-iteration run and should be
interpreted as mechanism-scale throughput, not statistical performance results.

Compilers and material flags:

- GCC 15.2 and Clang 21.1.8: `-std=c++20 -O3 -fno-stack-protector
  -march=native -Wall -Wextra -Werror`; generated headers were system includes
  so the consumer remained warning-strict without relitigating known corpus
  warnings outside this slice;
- Rust 1.98.0: `-O -C target-cpu=x86-64` for scalar and `-O -C
  target-cpu=native` for AVX2; and
- generated C++ and Rust used the same `extract_value_at`, `div`, and `load`
  source contracts.

Sub-cycle differences and the scalar Rust checked-load inversion are optimizer
scheduling effects at this scale, not claimed speedups. The robust observations
are:

- C++ unsuffixed AVX2 paths track the raw baseline. Checked lane/div validation
  is hidden by surrounding work in this input distribution; checked aligned
  load visibly pays its extent/alignment checks under GCC.
- Failure returns before the underlying division or memory operation and is
  consequently faster than valid work. The failure checksum remains zero; no
  placeholder is treated as a fallback value.
- Rust scalar lane/load codegen aliases the unsuffixed symbol to the raw symbol,
  but AVX2 primitive implementation calls are not fully inlined across the
  generated crate boundary. That pre-existing Rust codegen-quality issue costs
  about 3.4 cycles for lane extraction and 9.4 cycles for division relative to
  the raw consumer here; it is not checking overhead and was not introduced by
  the checked-API refactor.

checked value result is returned as an aggregate or through a vector output
pointer, and no result-only stack slot appears in the immediately consuming
checked call site. The separate negative controls still demonstrate the
aggregate-return and value-output costs.

The Rust caller counts intentionally expose, rather than hide, calls into
non-inlined generated implementation methods. Scalar Rust emits aliases for
raw/unchecked lane and load; C++ scalar and AVX2 unchecked lane/load probes add
no validation branch. Maintained generated-build assertions check these facts
semantically so compiler-address changes do not churn a committed hash baseline.

Benchmark executable `.text` sizes were 6,354/6,811 bytes for scalar C++
(GCC/Clang), 10,303/9,377 bytes for AVX2 C++, 368,414 bytes for scalar Rust,
and 370,978 bytes for AVX2 Rust. These include printing and benchmark plumbing;
the isolated instruction counts above are the useful mechanism measure.

## Editor and release-tool gates

The compiler-owned Python LSP suite passed 29 tests. The TypeScript client and
generated grammar passed 23 unit tests plus two grammar tests. The VS Code
integration suite passed both end-to-end cases using an explicit executable
from a workspace-local editable install, covering hover, diagnostics,
completion, source-owned precondition presentation, references, and semantic
tokens through the current server. The Linux x64 runtime smoke initialized in
0.812 s, published diagnostics in 6.243 s, and produced a verified 15.12 MB VSIX
with 193 files. No precondition vocabulary or decision logic was copied into
the TypeScript client or TextMate grammar.

## Conclusion

Final validation completed with 2,689 ordinary compiler tests passing and 121
expected opt-in/platform skips, 46 checked-API generated/ABI tests passing with
one unavailable-platform skip, and all 84 generated build/value gates passing.
Compiler type checking, the typed public-contract and checked-coverage
ratchets, strict C++/Rust documentation,
the two executable Rust doctests, GCC/Clang documentation consumers, Python LSP
tests, VS Code unit/integration tests, and the Linux x64 runtime-package smoke
gate also passed.

The checked representation achieves its intended C++ lever: callers opt into
validation without changing the unsuffixed path or forcing a value-owning
result aggregate. Rust's `Result` path is explicit and correct, but the
showcase also identifies an independent AVX2 cross-crate inlining opportunity.
The existing baselines prevent accidental typed-family and checked-coverage
drift, the checked census keeps every omission explicit, and package/doc gates
make generated artifacts reproducible. They do not yet prevent every emitted
qualifier, overload, parameter, result, visibility, or reachability change;
typed transitive-precondition accounting in Slice 9 and the exact backend
declaration manifest in Slice 10 remain TSL v1 release blockers. See the
[post-implementation review](tsl-v1-checked-api-post-implementation-review.md).
